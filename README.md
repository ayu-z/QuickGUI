# QuickGUI

面向 Windows 与 macOS 的 HMI 设计器。使用控件级 UI / CODE 属性编辑、可视化流程和真实 C 脚本构建可独立运行的桌面应用。

## 启动

需要 Node.js 22.12+、Rust 1.88+ stable；本机 C 构建需要 CMake 和 C 编译器。macOS 使用 Xcode Command Line Tools；Windows 的 Rust/MSVC 构建使用 Visual Studio C++ 工具链，TinyCC 引导另需 MSYS2/MinGW 的 shell、make 和 gcc。

```sh
npm ci
npm run setup:c
cargo build -p quickgui-c-runner
npm run desktop
```

只查看设计器和浏览器预览：

```sh
npm run dev
```

浏览器地址为 `http://127.0.0.1:1420`。浏览器可编辑工程、运行普通流程、测试绑定和导入导出工程；真实 C 与原生串口/USB/TCP/MQTT 操作使用桌面版。浏览器不会伪造这些执行结果。

## 工作流程

1. 从控件库点击或拖入控件，在画布移动、缩放、设置容器布局。
2. 选中控件，使用属性表单或 **CODE** 编辑该控件的 `props`、`style`、`states`。无效代码保留为草稿，最后有效画面继续显示。导出前必须处理草稿。
3. 在流程库使用数值、文本、布尔或JSON参数组件定义共享参数，在控件的绑定区域连接参数或事件流程。
4. 在流程页连接 FB 的执行端口与数据端口；条件节点使用 `true` / `false` 输出，事件支持手动、启动、定时触发。串口与 USB 各提供设备发现和通信两个 FB，通过多路命令入口及异步输出处理设备通信。
5. 在 C 脚本页编辑真实 C。通过 QuickGUI SDK 访问 JSON/字符串/数字输入输出、数字变量、状态和日志。
6. 打开预览。工程变化经过校验后更新；C 改动先只编译检查，失败时保持上一有效预览。原生预览有自己的运行会话和系统窗口。
7. 导出原始 `.qgui` 工程、独立源码工程或本机独立运行应用。

## 流程功能块

流程支持类似 PLC FB 的命名数据端口：数学与比较块可分别连接 A/B 参数，C 脚本块可配置多路输入和结果输出，输出可分接多个下游。新建节点默认显示 FB 端口；执行线与数据线分别表达触发和参数，工程统一使用最新 v5。详见 [流程功能块](docs/function-blocks.md)。

## 画布与详细属性

- 滚轮以鼠标位置为中心缩放（10%–800%）；空格拖拽或中键拖拽平移。标题栏提供 100% 和适应画布，窗口/模块分别记忆视图。
- 点击、Shift 点击或空白框选多个控件；拖动八个控制柄调整大小，Shift 保持比例。一次拖动、缩放或批量操作对应一次撤销。
- 右键菜单提供复制、剪切、粘贴、复制副本、删除、图层顺序、对齐和分布；图层树支持展开、重命名、锁定与隐藏。编辑器隐藏只影响设计视图，运行可见性用控件的 `visible` 属性控制。
- ⌘/Ctrl+C/X/V/D/A、⌘/Ctrl+Z、⌘/Ctrl+Shift+Z、Delete 和 Escape 对应常用操作；文本输入和 CODE 编辑期间保留文本编辑快捷键。
- 14 类控件使用统一属性定义，提供搜索、分组、重置/取消覆盖、状态样式及绑定约束。文本输入可设提交时机、只读和多行；选择框可配置选项值；图表支持最多 16 条曲线；表格可定义列、JSON 行数据、排序和选择事件。

跨工程粘贴先展示依赖清单，默认建立独立副本；可以逐项选择类型兼容的现有对象复用。默认保留源主题、语言与资源，可切换目标主题；导入的自动流程和附加窗口需要明确启用，C/React 代码需要确认信任。系统剪贴板不可用时明确提示使用当前进程内存，不能据此跨应用粘贴。

流程库提供 **数值参数／文本参数／布尔参数／JSON参数**，点击或拖入画布会一次创建共享变量及带类型输出的读取FB，支持单步撤销；无流程时会创建含手动入口的普通流程，不自动运行。左侧 **参数** 页签列出工程已有参数，可编辑定义或添加引用，多处引用共享同一稳定ID。右侧参数属性维护名称、类型、初值、运行值、单位、只读、持久化、质量与时间戳；JSON无效草稿不覆盖有效值。被引用的参数先清理引用才能改类型或删除；删除读取节点不会删除参数定义。旧工程变量及绑定保留，不改变工程格式。

独立数据页已移除。绑定路径仍为数组，例如 `["plant", "temperatures", 0]`；数字 `0` 表示数组下标，字符串 `"0"` 表示对象键。空路径表示整个参数，叶子写入保留兄弟数据，缺失路径不会自动创建。流程读/写节点也可设置路径。运行值编辑和手动运行须等待当前工程修订被运行时接受；更新期间“运行”按钮暂时禁用，避免执行旧图。

趋势图实时模式按可配置间隔采样；桌面历史模式查询现有 SQLite 数据，支持时间范围及 raw/avg/min/max/last 聚合。avg 为已存有效样本的算术平均；浏览器不提供 SQLite 历史。C 数字变量接口继续使用数字变量，JSON 通过脚本输入/输出传递。

数值参数的属性中展开 **历史与报警**，桌面运行时提供 SQLite 数值历史、阈值报警和报警确认。勾选参数的持久化选项后，重开同一工程可恢复类型兼容的值；设计器和预览的运行数据分别保存。

## 串口助手示例

串口工具箱提供“设备发现”和“通信”两个 FB。示例通过命令执行端口控制扫描、过滤、打开、关闭与发送，通过通信 FB 的 RX/TX/STATE/ERR 输出处理异步结果。

关闭当前工程后，在欢迎页点击 **打开串口助手示例**；也可打开 `examples/serial-assistant/quickgui.json`。这是可编辑、可导出的 v5 工程，使用 64 个普通控件和一张多入口流程图，集中处理设备发现、通信、收发记录与错误。不包含自定义 C 或 React 业务代码。详细操作见 [串口助手说明](examples/serial-assistant/README.md)。

示例节点默认带 FB 接口：发送内容、编码、行尾以独立数据线接入通信块的发送参数；RX/TX 输出分别提供完整报文和时间，用于历史与最近收发显示。

桌面运行时提供扫描、插入/拔出检测、VID/PID 筛选、持续连接、发送和监听。默认参数为 **115200 / 8N1 / 无流控**，接收使用原始批次；端口未选择、连接未打开，自动重连和定时发送均关闭。点击 **手动打开** 成功后开始监听；打开、连接和重连期间，端口、筛选及通信参数被锁定，需先断开再修改。

发送支持 UTF-8、HEX 和无行尾/LF/CRLF，定时发送默认 1000 ms、最短 100 ms，错过的发送不补发。HEX 必须包含完整字节，非法内容不发送；包含追加行尾的单次发送最多 65535 字节。发送成功表示操作系统写入完成，不代表设备应答。接收组帧可选 raw、LF 行或大端 length16；它只影响 RX，TX 始终直接发送编码后的内容与所选行尾，不自动添加长度头。已有设备请求流程沿用一次性诊断及串口8N1/无流控的收发语义。

设备通信通过流程组件触发。独立“连接”页已移除；已有工程中的连接配置、流程引用及运行行为保留，并随工程保存和导出。

严格自动重连默认关闭。手动打开后记录的 VID、PID、规范端口名与 USB 物理拓扑必须全部存在且完全匹配；不使用序列号或“唯一 VID/PID”替代拓扑。缺少信息时说明原因并要求手动打开。重连可恢复监听，但不会恢复定时发送。

显示历史保留最近 **500 条 / 512 KiB**，淘汰旧记录并统计淘汰量。未处理 RX 队列另有限制：**256 批 / 1 MiB**；过载会立即断开、停止待发送任务和定时发送，锁存故障并暂停重连，需手动打开恢复。清空显示历史和重置累计计数是两个独立操作。

浏览器可编辑此工程并验证普通绑定/数据流程；原生串口操作会给出真实能力诊断，不提供模拟设备或 Web Serial。浏览器检查、PTY/回环自动化和实体设备验收分别记录，不能互相替代。

## 自定义 React 组件

组件目录包含 `manifest.json`、TSX 入口及可选 CSS。示例目录 `examples/components/status-card` 可直接构建：

```sh
node scripts/build-component.mjs examples/components/status-card artifacts/status-card.qgcomponent
```

在设计器的“模块 → 导入组件包”中选择生成文件，确认信任代码后添加实例。实例的属性和样式仍通过 UI / CODE 编辑，组件声明的事件可连接流程。组件内部在 ShadowRoot 中挂载独立 React 根以隔离样式；这不是代码安全沙箱。

组件包保留完整源码；独立工程导出会提取组件源码并提供标准 esbuild 重建入口，修改 TSX 后可在脱离设计器的环境继续构建。

组件 manifest v2 可声明 `propertyDefinitions`，与内置控件共用属性类型和绑定描述。组件包 v2 同时保存源主题、翻译和图片。跨工程复制保留原始源码身份与本地模块 ID 的区别，不改写 TSX 或 C 源字符串。

在独立源码目录修改组件后，同时更新包及 `project.json` 中的运行 bundle：

```sh
node scripts/build-component.mjs components/<localId> artifacts/<localId>.qgcomponent --project project.json --module <localId>
```

工具按本地模块 ID 定位，校验成功后原子更新工程，保留原包身份及资源作用域。只输出组件包而省略 `--project/--module` 不会修改工程。

## 工程命名

在欢迎页或顶部工程菜单选择 **新建工程**，填写名称后创建空工程。已有工程可点击顶部工程名称 → **重命名工程**。名称会去除首尾空格，不能为空、含控制字符或超过 200 个字符。

工程名称用于工作区显示、恢复副本和保存/导出的建议文件名；文件名中的路径符号等不兼容字符会替换，过长文件名会截短，工程内的名称完整保留。新建时窗口标题初始采用工程名称；后续重命名只修改工程名，窗口标题与发布应用名分别在窗口属性和项目配置中编辑。工程 ID 保持不变，历史数据仍对应原工程。

## 关闭工程

点击顶部工程名称 → **关闭工程**，可以选择：

- **保存工程并关闭**：先保存/下载工程文件，再停止运行并返回空工作区。有未应用的 CODE 草稿时，需要先处理草稿才能导出。
- **保留恢复副本并关闭**：将当前内容和 CODE 草稿保存到本机恢复区，停止工程后可从欢迎页恢复。恢复区保留最近一次副本，不代替长期文件备份。
- **取消**：继续编辑当前工程。

关闭会取消流程、定时源、在途 C/连接任务和构建，关闭独立预览，并将运行数据刷新到 SQLite；串口监听、设备观察和所属端口会话一并清理。原始文件和历史数据库不删除。持久化失败时保持工程打开并报告错误，可以重试。关闭后刷新设计器仍停留在空工作区，不会自动生成另一个工程。新建工程从空窗口开始，泵站和串口助手示例可以从欢迎页单独打开。

## 工程版本与兼容性

JSON 保存的是工程数据，也包含 C 源码、资源及自定义组件源码/bundle；内置控件和运行引擎仍由设计器提供。因此，仅保存 JSON 不能保证未来任意设计器版本都能无损打开和运行。

工程统一使用最新 `schemaVersion: 5` 和控件 `definitionVersion: 2`。新建、打开、恢复、复制和导出直接使用当前模型，已知旧文档在入口一次性转换，无升级弹窗，撤销编辑不会回退工程版本。不保留旧版本的渲染或流程运行分支。未知版本、未知结构和无效引用仍严格拒绝。详见 [工程格式说明](docs/project-compatibility.md)。

## 多窗口工程

左侧 **窗口** 下拉框管理同一工程的窗口，支持 1 个主窗口和最多 31 个附加窗口；窗口与流程使用相同的下拉选择方式，支持键盘选择。

1. 点击 **新增窗口**，输入名称后创建空布局。在下拉框中切换当前编辑窗口；每个窗口独立设置标题、尺寸、图标、背景、圆角和控件，主窗口带有明确标记。
2. 选择与新增入口合并为一行。选中附加窗口后，在右侧 **窗口属性** 中重命名、删除，并设置 **启动时打开此窗口**；选中控件时可点击顶部窗口属性按钮返回。主窗口始终存在。删除含未应用 CODE 草稿或被流程引用的窗口前，需要先处理草稿或引用；窗口新增、编辑和删除支持撤销。
3. 在流程页添加 **窗口操作** 节点，选择目标及打开、聚焦或关闭操作，再把控件事件绑定到该流程。打开/聚焦会复用已有窗口，聚焦关闭状态的窗口会将其打开。流程不能关闭主窗口。
4. 点击 **预览** 会打开当前编辑窗口。桌面版使用多个原生窗口；浏览器在预览工作区展示可拖动的窗口，并提供打开/关闭入口。各窗口共享变量、流程、连接、C 脚本与模块；关闭子窗口不会停止共享业务流程。

热更新保留窗口开闭状态和兼容的变量值。关闭后重新打开子窗口不会重新执行启动流程；桌面版关闭主预览会清理该预览组，关闭工程会清理全部所属窗口和运行任务。浏览器收起预览后仍保留工程运行状态。工程导出保留全部窗口；独立源码和运行应用沿用同一多窗口模型。原生窗口位置按工程和窗口分别记录。

## 窗口与图标

界面 LOGO 使用 `public/quickgui.svg` 中按品牌参考图重绘的折叠 Q 矢量，顶部显示为 28px、欢迎页为 64px；桌面 LOGO 使用 `src-tauri/icons/app.svg` 中的白底圆角版本，底板占画布约 79.7%，四周保留透明空间。运行 `npm run icons` 会从桌面矢量源重新生成 PNG、ICO 和 ICNS，桌面构建也会执行该步骤。素材独立存放于对应目录，运行、构建和独立源码导出均不依赖原素材目录。

点击窗口属性设置原生窗口标题、尺寸、限制、置顶、全屏、位置恢复、内容背景与圆角。窗口外框使用系统样式：Windows 11 可选系统默认、方角、圆角或小圆角；macOS 使用系统外框。

应用图标、窗口图标和 Windows 桌面快捷方式图标可独立配置。图像存入工程，构建时生成 ICO/ICNS。应用包和快捷方式图标随发布更新，预览图标不会替换设计器的应用图标。

顶部栏整合工程菜单、工作区页签和常用操作；常规宽度单行显示，窄窗口自动分行。**项目配置** 位于 **C 脚本** 后，统一设置应用名称、应用标识、版本号、发布者、应用图标和桌面快捷方式；这些配置对整个工程生效，当前窗口的标题、图标及行为仍在窗口属性中编辑。项目配置默认隐藏运行日志，构建时可显示输出；切页保留其他工作区的日志显示偏好。

工作空间的 **界面 → 应用外观 → 多语言 → 流程** 分别管理布局、工程主题、翻译及逻辑。**应用外观** 提供 **亮色／暗色**，切换已保存的对应方案，支持撤销并同步画布、预览与导出。仅同步与原主题背景色匹配的窗口背景，控件固定颜色、独立组件资源及自定义窗口背景保留。设计器工具栏的主题按钮独立控制编辑器外观。

**应用外观** 的颜色表分为 **索引／亮色／暗色** 三列，每种主题都有独立的色块与颜色值。编辑当前方案会同步界面，编辑另一方案只保存对应颜色；切换主题不会重置已编辑值。输入 `brand`、`color.brand` 或 `$color.brand` 可添加一对颜色，以 `$color.brand` 引用；重复索引会被拒绝，新增颜色可撤销。旧工程首次编辑或切换时保存两套方案，当前颜色保持，另一套内置颜色使用默认值，自定义颜色默认继承原值。

控件样式通过 `$color.primary` 引用主题。**多语言** 使用紧凑表格：首列为索引，例如 `pump.title`，控件文本通过 `@pump.title` 引用；第二列起每列对应一种语言，翻译使用32px高的单行输入框。只有一至两种语言时全部展开，三种及以上语言可点击列头展开或收起，同时最多展开一列，也可全部收起；增删语言或撤销重做自动切换布局。首列固定，语言较多时可横向滚动，展开列自动滚动到可编辑位置。未设置翻译仍沿用默认语言回退，显式空文本保持为空；已有多行翻译未经编辑时保留原文。索引重命名后需同步调整控件的 `@key` 引用。定义字符串变量 `locale` 后，可由绑定/流程在运行时选择 `ja-JP` 等工程已有语言。

应用外观与多语言页使用全宽表格、紧凑工具栏及可展开的使用说明，固定表头和索引，表格占据剩余空间。配置页默认不显示运行日志，返回界面或流程页保留原开关状态；构建应用时仍可显示实时构建输出。双色方案的工程兼容性见 [工程格式说明](docs/project-compatibility.md)。

## 原始工程和源码交付

`.qgui` 是包含 `quickgui.json` 的 ZIP 工程包；也可直接打开 JSON。图片、C 源码、模块定义与依赖信息随工程保存，路径不依赖原机器。

命令行导出可独立开发的源码工程：

```sh
node scripts/export-project.mjs path/to/quickgui.json path/to/export
```

导出包含 React 渲染器、Rust 引擎、C SDK/源码、原生宿主和构建脚本，使用标准 npm/Cargo/CMake 工具，不需要 QuickGUI 设计器或 CLI。源码导出为单向快照；任意修改后的 React/Rust/C 代码不自动逆向为设计器控件。

在导出目录构建原生应用：

```sh
npm ci
node scripts/build-native.mjs --aot
```

发布默认提前编译 C。普通使用者无需 Node、Rust、CMake、C 编译器或设计器。首次源码构建通常需要联网下载依赖；完全离线重建需要预先准备包缓存。

Windows 设计器及导出应用的发布包不内置 WebView2 运行时或离线安装器，使用系统已安装的 WebView2。目标电脑缺少运行时时，安装器会联网下载并安装；离线安装前需自行准备 WebView2，直接运行 EXE 也需要系统已安装该运行时。

构建设计器本身：

```sh
npm run desktop:build
```

Windows 和 macOS 应在各自系统上构建。开发者证书、Apple 公证及 Windows 签名凭据不包含在工程中。未提供签名凭据的本机构建不等于完成公开分发签名。

## 验证

```sh
npm run check
npm run build
npm run test:e2e
cargo test --workspace
npm run test:c
```

首次运行浏览器测试需 `npx playwright install chromium`。真实 C 测试需要先执行 `npm run setup:c`。验证记录和平台边界见 `docs/verification.md`；架构与数据契约见 `docs/architecture.md`；C API 见 `sdk/README.md`。

## 当前工程约定

- 本地恢复数据保存在设计器 WebView 的本地存储；导出工程才是可搬运的持久交付。
- 运行日志有界，变量值与模块可序列化状态在兼容的热更新中保留。
- C 模块是可信本机代码；子进程用于故障隔离，不宣称构成恶意代码安全沙箱。
- 所有源文件变更记录于 `CHANGELOG.md`。是否初始化 Git 与提交状态按用户授权处理。
- CI 定义三种目标架构；本地测试只能证明当前实际执行的平台，不能代替其他平台的 CI 或实机验收。
