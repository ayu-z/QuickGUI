# 工程格式与设计器升级兼容性

## JSON 中有哪些内容

当前工程是 `quickgui.json`，`.qgui` 则是包含该 JSON 的 ZIP。JSON 内嵌窗口和控件属性、样式、绑定、流程、变量、C 源码、图片 data URL、自定义 React 组件源码及编译 bundle。它不只是布局描述，但也没有包含设计器提供的全部内置控件、Rust 引擎及编译工具链。

## v1 单窗口与 v2 多窗口

设计器读取 `schemaVersion: 1/2/3/4`。有效 v1–v3 工程仍按原版本读取、保存和导出，不会仅因打开工程就添加字段或改变版本；普通新建空工程仍使用 v3，串口助手示例使用 v4。

两种格式的 `window` 与 `widgets` 都表示固定主窗口，逻辑 ID 为 `main`。v2 增加必需的 `windows` 数组，最多包含 31 个附加窗口；该数组不包含主窗口。每个附加窗口包含 `id`、`name`、`config`、`widgets`、`openOnStart`。v1 不允许出现 `windows` 字段，即使它是空数组。

附加窗口 ID 为 1–64 个 ASCII 字符，以英文字母开头，之后只允许英文字母、数字、下划线和连字符，且不能等于 `main`。窗口名称不能为空或全为空白；校验不会裁剪合法名称的原有空格。所有窗口中的控件 ID 在工程内唯一；控件父子关系只能指向同一窗口内的控件，并且不能成环。模块定义中的控件使用各自的局部作用域；模块内部引用与暴露属性目标也会被检查，模块之间不能循环引用。显式 `windows: null` 在两个版本中都不是合法格式。

变量、流程、C 脚本、模块、资源、连接和翻译继续属于整个工程。附加窗口的图标、绑定、模块与流程引用也必须有效，不能仅校验主窗口。窗口配置沿用原有规则，包括最小尺寸不能大于初始尺寸。

为 v1 添加附加窗口或 `window` 流程节点时，编辑器将工程显式升级为 v2，并写入 `windows` 数组；已有 v3/v4 不降级。窗口节点使用 `action: open | close | focus` 和存在的 `windowId`；禁止关闭主窗口。删除最后一个附加窗口后，可以保留 `schemaVersion: 2, windows: []`，不会自动降级或丢弃窗口节点。

只支持 v1 的旧设计器会拒绝 v2 的版本号，不会把附加窗口当作未知数据忽略后覆盖原工程。当前设计器拒绝 v5 及其他未知版本；不会猜测迁移未知格式。只支持到 v3 的设计器同样不能打开 v4 工程。

`listProjectWindows` 返回主窗口和附加窗口，主窗口的名称取自 `window.title`，`openOnStart` 固定为 `true`。`getProjectWindow` 对不存在的 ID 抛出错误，不会回退为主窗口。`projectForWindow` 只是给渲染器使用的视图投影，不能传给运行引擎、保存或导出；这些入口始终使用完整工程。编辑器当前选中的窗口属于界面状态，不是主窗口定义。

独立源码导出保留工程实际版本的完整 JSON；v2–v4 的 Tauri 配置仍只声明原生主预览窗口。附加窗口由运行时根据工程及窗口状态动态打开，避免静态创建窗口时重复启动执行引擎。

## 目前会遇到的不兼容情况

- 工程的 `schemaVersion` 不是当前支持的 1、2、3 或 4，包括 v5。
- 工程使用当前设计器没有的控件、流程节点或结构字段。
- 虽然格式仍为 v1，内置控件、布局、绑定或流程的运行语义发生改变，导致旧工程效果不同。
- 自定义组件依赖的宿主接口发生改变；组件版本号本身尚不能阻止不兼容升级。
- C SDK、编译器、操作系统或外部设备依赖发生变化。C 的 ABI/执行器能力检查能发现一部分问题，不能替代完整兼容测试。

工程的 `revision` 只是编辑次数，不是文件格式或运行时的兼容版本。运行快照中的可选 `windowState` 描述已打开窗口、焦点和窗口状态修订号，不写入工程文件。当前还没有最低设计器版本或所需功能清单。

## 本次已实施的保护

- 在解析工程前检查 `schemaVersion`，给出明确的版本错误。
- 所有固定结构采用严格校验。未知字段列出 JSON 路径，并提示可能来自较新设计器；不再通过 Zod 默认行为静默移除字段。
- 明确开放的属性、样式、主题与翻译映射保持原有语义；结构严格校验不等于禁止组件自定义属性。旧节点 config 沿用原规则，v4 新节点按各操作的字段白名单校验。
- 校验是只读操作。拒绝导入不会修改传入对象或原始文件；恢复失败不会用示例覆盖原恢复数据。
- 继续保留原始工程及独立源码导出。独立源码包包含当时的 renderer、engine、C SDK、组件源码、构建脚本和依赖锁文件。

这些是防止数据丢失的保护，**不是“所有未来版本都向后兼容”的承诺**。严格拒绝能保护原件，但当前设计器不会自动理解或转换未知能力。

## v3 与控件属性版本

v3 保留 v2 的主窗口和 `windows` 数组，新增 JSON 变量、类型化绑定路径、C 变量别名、资源作用域、模块原始身份和属性元数据，以及控件 `definitionVersion`、`editor` 状态。控件属性版本与工程格式分别管理：缺省/1 使用原渲染行为，2 使用详细属性语义。旧工程升级只标记现有控件为 1；不会顺带改变全部控件。

请求新属性或锁定/隐藏、JSON 数据、跨工程粘贴等能力时，先显示升级说明，确认后更新工作副本；取消不改变模型，确认与后续操作一起撤销。原文件不会自动覆盖，应另存新版。明确升级控件时，旧趋势 `value` 和绑定转换为第一条曲线，表格首行转换为列标题，其余行成为数据；选择框保留旧格式化标签和值，文本输入保持失焦提交。未知扩展字段保留；新约束无法表示的配置拒绝升级并回滚。

绑定的 `path` 为字符串/非负整数数组，最长 32 层；数组下标必须使用数字。省略或 `[]` 指根值，非空路径要求 JSON 变量。JSON 值上限 1 MiB、32 层，缺失与 null 分开处理，写入必须命中现有路径，整次校验成功才替换。属性目标的 JSON Pointer（如 `/series/0/value`）是另一套路径表达，不直接充当变量路径。

跨工程粘贴建立依赖闭包并分配本地 ID，复用必须明确选择；代码不做字符串替换。C `variableAliases` 和 React `packageIdentity` 分别保留源码引用与包身份。同一打开会话内复制保留共享引用及原版本；同 ID 的另一个工程会话仍走依赖审阅。组件包兼容原始格式，v2 envelope 增加属性元数据和嵌入资源；旧导入器可能拒绝，应保留原包及独立源码。

## v4 串口与通用数据流程

v4 保留 v3 的工程和控件语义，增加 `serial`、`map`、`append` 节点，以及 `serial`/`controlledInterval` 事件入口。添加这些能力或启用完整串口 profile 前，设计器提示升级工作副本；取消不改模型，确认后的升级及操作构成一次可撤销变更。已有 v4 不被 v3 功能操作降级，也不自动将所有旧控件升级为属性版本 2。普通空工程继续为 v3；不需要串口的工程无需迁移。

`ValueRef` 明确标识 `literal`、`input` 或 `variable`，变量引用采用稳定 ID，可附带原有类型化 JSON 路径。新节点 config 严格检查操作、字段、值来源、范围及引用，边必须使用合法端口。串口有状态操作必须指向已声明的 serial 连接；端口句柄、运行中的 sessionId、扫描结果和收发历史不会作为连接 profile 保存。示例通过普通 JSON 变量、绑定和流程传递这些运行值。

`serial`/`map`/`append` 使用 `success` 和 `error` 端口；省略输出端口表示 success。既有 condition 仍使用 true/false，其他旧节点保持原端口与运行行为。v4 手动运行只进入手动事件节点，不会替外部串口事件构造输入。原有 `connection` 单次诊断不因升级为 v4 变成持续串口会话；其 8N1/无流控及收发组帧语义保留。v4 的接收组帧则仅作用于 RX，发送只按编码与所选行尾直接写入。

剪贴板依赖分析包含嵌套 ValueRef、append 目标变量、串口连接及外部事件生产者；复制不会将字符串常量误作引用改写。跨工程导入 v4 内容会在依赖审阅中保留 v4 格式要求，自动流程默认禁用；需要明确启用，避免导入立即访问设备。工程加载的执行内容检查同样覆盖串口事件和受控定时器。删除仍被这些节点引用的变量或串口连接前，应先解除引用。

源码导出携带对应版本的运行器、原生串口服务和验证规则，示例可脱离设计器继续构建。浏览器支持布局、普通绑定及数据流程，但不能据此验收原生串口；缺少能力时返回明确诊断，不模拟成功。实体设备、USB 物理拓扑和平台驱动仍须单独验证，不能由工程格式校验、PTY 或回环测试证明。

## 长期归档建议与后续策略

每次正式交付同时保存原始工程包、独立源码包、已验证运行包及对应设计器版本。独立源码可以脱离后来版本的设计器继续构建；构建仍受 Node/Rust/C 编译器及平台工具链影响，锁文件不等同于完整冻结环境。

未来需要改变已有字段或运行语义时，应升级格式/API 版本，提供生成副本的迁移函数与报告，并用历代工程样本验证读取、往返保存、布局和流程结果。当前 v2 保留 v1 的主窗口字段，只有使用新增能力时才升级版本；这不构成任意未来格式的自动迁移机制。设计器版本、运行时/组件 API、C ABI、组件哈希和工具链记录仍需各自管理。
