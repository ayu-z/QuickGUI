# 工程格式与自动升级

工程统一使用最新 schemaVersion 5，控件统一使用 definitionVersion 2。新建、打开、恢复、复制、保存和独立源码导出使用同一个当前模型，不再显示版本升级确认，也不维护旧版渲染或流程执行语义。

## 入口与校验

已知 v1–v4 文档只在入口一次性转换到 v5；缺少的附加窗口数组补为空，旧控件属性转换到现代结构。转换只处理工作副本，不自动覆盖原文件。转换后的工程先通过完整校验才替换编辑器有效模型。撤销、重做和同工程粘贴保持 v5 与控件版本 2。

缺少版本、未知未来版本、未知结构字段、重复 ID、失效引用和无效类型仍拒绝；无效 CODE 或端口草稿不得覆盖有效模型。属性、主题、翻译与节点配置中明确开放的扩展映射可保留数据。无法无损转换的冲突配置会报告错误。

控件转换包含：趋势 value/绑定转第一条曲线，表格首行转列标题，选择框转类型化选项，输入框转换提交设置。转换完成后统一使用当前属性校验、绑定与渲染。新建控件直接使用现代默认值。

## 当前工程模型

window/widgets 表示固定主窗口 main；windows 是必需数组，最多保存 31 个附加窗口，每个包含稳定 ID、名称、配置、控件和 openOnStart。所有窗口共享工程级变量、流程、脚本与资源，不能通过窗口流程关闭 main。

JSON 变量和绑定路径、C 变量别名、资源作用域、组件身份、串口会话/事件、受控定时器、map/append 节点及 FB 命名数据端口均可直接使用。组件包版本与 C ABI 独立管理，不因工程版本自动改变。

### 亮暗双色方案

v5 主题新增可选 `palettes` 字段，包含 `light` 和 `dark` 两个字符串映射。两套键集合必须与 `tokens` 一致，`tokens` 必须等于 `mode` 对应方案；`system` 使用保存的暗色列作为有效值，继续沿用既有系统模式行为。缺少任一方案、未知字段、键不齐或有效颜色不一致会拒绝导入，不静默修改输入文件。资源作用域和组件包使用同一校验规则。

不含 `palettes` 的旧工程仍可直接打开、预览及原样导出；只查看双色表不修改工程。首次编辑颜色、添加颜色或切换主题时才生成两套方案：当前模式保留原 `tokens`，另一套的内置颜色使用对应默认值，自定义颜色继承原值，不补入旧工程缺失的令牌。原 `mode=system` 的有效值保留在暗色方案。编辑非当前列仅更新保存值，切换时更新有效令牌及匹配旧主题背景的窗口。

双色方案是当前 v5 的可选主题扩展，保存后需要支持此字段的新版设计器；旧设计器采用严格校验，会将 `theme.palettes` 视为不支持字段而拒绝打开，不保证旧版向前兼容。原始工程、源码导出、组件包及跨工程资源复制保留两套方案；运行器沿用有效 `tokens`，无需根据表格布局解释颜色。

## 统一运行语义

设计态、浏览器预览和独立应用使用相同流程模型：math 拒绝隐式数值转换，eq/neq 按 JSON 结构比较，条件转发原输入，write 转发实际写入值。手动执行只进入手动事件节点，自动源按真实事件触发。执行域持续运行，流程完成不停止其他事件；逻辑编辑取消旧工作，纯外观热更新保留有效执行。

FB 执行线和数据线分离，支持命名多路输入、输出与分接；C 状态按块实例隔离。未配置 block 的节点使用相同执行器的标准输入/输出，不启用旧版调度器。详见 [流程功能块](function-blocks.md)。

## 复制与交付

同一工程会话复制共享引用；跨工程复制先审阅依赖、资源和代码信任，使用当前模型和稳定 ID 重映射。源码导出保留完整 v5 工程，Tauri 只静态声明主预览窗口，附加窗口由运行时动态创建。命令行导出复用工程校验器；原生导出接收设计器已校验的当前文档。

浏览器缺少 C、串口、SQLite 或原生窗口能力时给出明确诊断；浏览器测试不替代真实设备、签名或性能验收。
