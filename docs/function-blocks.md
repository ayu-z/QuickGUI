# 流程功能块

工程统一使用最新 v5，新建流程节点默认显示 FB 数据端口。打开或恢复已知旧文档时自动转换到当前模型，不再要求确认升级。已有未配置接口的节点可点击 **启用 FB 端口**，接口编辑可撤销，工程版本始终保持 v5。

## 连线与执行

- 三角端口和实线是执行信号。`EN` 触发一次执行，`ENO`/`DONE` 表示完成，条件块保留 `TRUE`/`FALSE` 分支；FB 的 `ERR` 可连接错误处理。
- 圆形端口和虚线是数据。输入接收一个数据源，输出可以分接多个下游。number、boolean、string 按相同类型连接，json 输入接受任意 JSON 类型；执行线和数据线不能混接。
- 数学块具有独立的 A、B 输入；比较块具有 A、B 输入和布尔 Q 输出；延时块具有 IN 和 PT 输入；串口块按操作显示数据、编码、超时等参数。未连线的参数沿用节点配置，或使用端口设置的默认值。
- 数据线本身不触发下游。没有连接 EN 的块在已触发的下游需要其结果时求值，同次流程执行内复用结果。例如：两个读取变量块的数据输出分别接数学 A/B，数学 Q 接写入 IN，事件执行线接写入 EN。
- 连接了 EN 的块必须先在本次执行中产出数据。未触发的分支不能提供上次执行的残留结果；缺失数据、错误类型和缺失输出路径会报告明确诊断。数据缓存按每次流程执行隔离，并发执行不会混用数据。
- 数据依赖和执行依赖一起检查循环。需要重复工作时继续使用事件或定时源。

同次执行中，一个块通过多条执行线被触发时仍会执行多次；数据消费者读取该次执行中该块最近一次完成的结果。没有 EN 连线而按需求值的块只执行一次，多路输出共享这次调用。

## 可运行示例

USB 和串口各提供 **设备发现**、**通信** 两种 FB。发现块通过 `SCAN`、`WATCH`、`UNWATCH` 控制枚举和设备变化监听；串口发现块另有 `FILTER`，可在浏览器中过滤已有端口数组。通信块通过 `OPEN`、`CLOSE`、`SEND` 等独立执行入口操作同一持久会话，`RX`、`TX`、`STATE`、`ERR` 是独立异步输出，无需另建原生事件组件。命令结果从 `DONE` 输出；默认 Q 为结果，DATA/STATE 仅在对应异步输出时提供载荷。错误信息沿 ERR 执行消息交付。

USB 由 [usb_comm_rs](https://github.com/dev-zuihong/usb_comm_rs) 提供 HID 与 Windows USB Print 原生实现；通信节点的相同 `sessionId` 共享会话，串口节点通过相同连接 ID 共享会话。USB 发现结果含精确设备 ID 和原始路径，`device` 接该对象或 ID；重新插拔后需重新发现。打开和发送必须由命令执行线触发，数据线不会按需打开或发送。原生异步输出可直接作为流程入口。

欢迎页的 **USB 助手示例** 将发现、热插拔、手动打开/关闭/发送及 RX/TX/STATE 分流整合在一张图中，共用一个发现 FB 和一个通信 FB。打开 [USB 工程](../examples/usb-assistant/quickgui.json)，或参阅 [操作说明](../examples/usb-assistant/README.md)。浏览器明确返回原生能力诊断，不生成设备或收发结果。

欢迎页的 **泵站示例** 提供 **FB · 调速计算** 流程：目标百分比和额定转速接入数学块，结果块使用 `RPM` / `MARGIN` 双输入双输出；`RPM` 分接至结果变量与日志。默认 65%、3000 rpm 得到 1950 rpm 和 35% 余量，浏览器与桌面均可运行。可直接打开 [泵站工程](../examples/pump-station/quickgui.json)，步骤见 [示例说明](../examples/pump-station/README.md)。

[串口助手](../examples/serial-assistant/README.md) 将原来分散的操作整合到一张多入口图中。手动/定时发送共用通信 FB 及发送内容、编码、行尾三路数据；RX/TX 的报文与时间输出分别连接历史与最近收发显示。原生串口操作要求桌面运行时。

## 同一流程的多个事件入口

控件的“事件与流程”可同时选择流程和其中的手动事件入口。多个按钮可进入同一张图的不同位置，只有所选入口被触发；原始事件载荷保持不变。启动、定时与原生异步输出继续由各自真实事件源触发。

日志栏的“运行入口”可选择具体流程与手动入口，再点击运行。含多个手动入口时，未指定入口的运行请求会被拒绝，避免一次启动整张图的全部操作。

`widget.events` 的值可以是单入口流程 ID，或精确绑定 `{"flowId":"main","entryNodeId":"open-event"}`。含多个手动入口的流程必须使用精确绑定；缺失、非事件及自动入口会在模型校验时被拒绝。增加第二个手动入口时，已有控件绑定保留原入口；删除入口时清理对应绑定。跨工程复制、工程保存和独立源码导出同步保留并重映射流程与入口 ID。

## C 脚本的多路端口

选中 C 脚本块，在 **FB 数据端口** 中添加输入、输出，每侧最多 16 路。输入设置字段名、类型和默认值；输出设置名称、类型及结果路径。点击 **应用端口** 后生效，无效草稿不覆盖已应用接口。

命名输入组成 JSON 对象，C 通过已有 `qg_input_json()` 读取，例如 `{"a":10,"b":4}`。脚本使用 `qg_emit_json()` 返回结果，例如 `{"sum":14,"difference":6}`；SUM 输出路径为 `["sum"]`，DIFF 为 `["difference"]`。`[]` 表示完整结果，也可投影数组中的字段。整数参数的 C 回归示例见 [function-block.c](../sdk/tests/function-block.c)。

同一脚本定义可用于多个 FB 实例。`qg_state_get/set` 状态按流程 ID、节点 ID 和脚本 ID 隔离；相同实例的后续调用保留状态，不同实例互不覆盖。普通脚本节点和直接执行脚本继续使用原来的脚本状态语义。SDK ABI 与工作进程协议保持不变，JIT 和发布时的 AOT 使用相同参数与输出。

端口 ID 与显示名称分别保存，改名保留连线。移除端口后应用会移除对应数据线；改变已连线端口的类型必须先处理不兼容连接。跨工程复制与独立源码导出保留接口、端口 ID 和连线。

切换设备发现/通信类型时，参数端口随类型更新，仍适用的端口保留 ID、名称、默认值与连线；清理已移除的参数和命令连线。读取/写入块创建时根据所选变量推断类型，后续更换变量可在端口编辑器中调整类型。

## 工程格式

v5 节点的可选 `block` 包含 `version: 1`、`inputs` 和 `outputs`。输入保存稳定 `id`、显示 `name`、`type`、`binding` 及可选 `key`/`defaultValue`：`input` 替换主输入，`config` 提供内置参数，`field` 组成命名 JSON 输入。输出保存 `id`、`name`、`type` 和类型化 JSON `path`。

未标记 `kind` 的边仍是执行线；数据边使用 `kind: "data"`，句柄分别为 `data-out:<端口 ID>` 与 `data-in:<端口 ID>`。接口版本、未知字段、稳定 ID、类型、重复输入源和循环均严格校验。保存和导出只使用当前模型；不保留旧版运行分支，未知未来版本仍拒绝。

浏览器、设计态与独立应用使用相同端口语义；C 和原生设备仍要求桌面运行器。浏览器端口测试不代表真实 C 或设备验收。
