# 串口助手示例

`quickgui.json` 是一个可直接编辑、保存和导出的 QuickGUI v4 工程。它包含 64 个普通控件、16 条可视化流程和一个串口连接 profile；没有自定义 C/React 业务代码、模拟设备或 Web Serial。生成器位于 `src/examples/serialAssistant.ts`，欢迎页通过通用示例注册表创建独立工程副本。

## 打开与运行

1. 启动 QuickGUI 桌面版；从源码开发时，在仓库根目录按主 README 完成工具链准备，再运行 `npm run desktop`。
2. 关闭当前工程，在欢迎页选择 **打开串口助手示例**；也可使用“打开工程”选择此目录的 `quickgui.json`。从文件打开含自动事件源的工程时，先审阅并确认信任。
3. 在桌面预览中扫描端口并选择目标。VID/PID 可留空，或输入可带 `0x` 的 1–4 位十六进制；两者同时填写时必须同时匹配。没有 USB 标识的设备不匹配指定 VID/PID。
4. 核对通信参数后点击 **手动打开**。成功后自动开始监听，可使用开始/停止监听及断开按钮控制会话。
5. 输入发送内容，选择 UTF-8/HEX 与行尾，点击 **发送**。收发记录、时间及累计字节/批次数显示在右侧；清空记录不会重置累计计数，重置计数不会删除已显示记录。

浏览器开发模式 `npm run dev` 可编辑界面、绑定和流程，也可导出工程。扫描、打开、发送等原生操作会明确提示需要桌面运行时；不会生成示例端口、伪造接收数据或显示假连接成功。

## 默认值与限制

| 项目           | 默认或规则                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| 连接           | 未选择端口、未打开、未监听                                                 |
| 通信参数       | 115200 波特、8 数据位、1 停止位、无校验、无流控                            |
| 接收组帧       | raw 原始读取批次；还可选 LF 行或大端 length16                              |
| 发送           | UTF-8、无追加行尾；可选 HEX、LF、CRLF                                      |
| 定时发送       | 关闭；间隔默认 1000 ms，允许 100–86400000 ms；忙碌或错过的 tick 不积压补发 |
| 自动重连       | 关闭；启用后仍须满足严格同设备条件                                         |
| 显示历史       | 最近 500 条且最多 512 KiB，超限淘汰旧记录并累计淘汰量                      |
| 未处理 RX 队列 | 最多 256 批或 1 MiB；过载立即断开并锁存故障                                |
| 单次发送       | 编码及追加行尾后的总量最多 65535 字节，超时默认 5000 ms                    |

**接收组帧只影响 RX。** TX 将编码后的字节与所选行尾直接写出，不自动加 length16 长度前缀，也不去除内容中已有的行尾。例如 HEX `41 0A` 再选择 LF，实际发送 `41 0A 0A`。HEX 允许连续字节或 ASCII 空白分隔，但必须是完整字节对；非法 HEX 不发送。部分写入或超时不自动重试，写入成功仅代表操作系统接受，不代表设备应答。

打开中、已连接或重连期间，端口、VID/PID 筛选和通信参数锁定；先断开再更改。停止监听只停止数据事件交付，端口可继续排空并统计数据，恢复监听不会补播停止期间的数据。断开、故障和重连均停止定时发送。

## 严格重连与过载恢复

严格重连以手动成功打开的设备为基准，要求 **VID、PID、规范端口名和 USB 物理拓扑（busId/portChain）全部存在且完全相同**。换设备、换端口或换 USB 位置须手动打开建立新基准。缺少拓扑时不能用序列号或“唯一 VID/PID”代替，运行时会说明不能自动重连的原因。恢复连接后可恢复监听，但不会自动恢复定时发送。

显示历史淘汰与未处理接收队列过载是不同状态。发生 `RX_OVERFLOW` 时，运行时关闭端口、取消待发送任务和定时发送，并暂停自动重连。排除持续过载原因后点击 **手动打开** 恢复；清空显示记录不会解除该锁存。

## 修改流程和导出

扫描和设备变化流程把端口快照经过 VID/PID 筛选、通用 map 节点映射成下拉选项。打开、监听和发送均使用 serial 操作节点；发送参数由工程变量提供。RX/TX 事件各记录一次历史，通用 append 节点限制显示容量；发送操作返回结果不会再次追加一条 TX 记录。状态及错误通过独立事件流程更新界面。

所有按钮、控件属性、JSON 绑定、ValueRef 来源和流程连线都可在设计器中修改。新串口/数据节点使用 success/error 端口，错误包含 code/message；未连接错误出口时，该次执行失败并记录诊断。此工程使用 v4；普通新建空工程仍是 v3，添加 v4 能力时需确认升级。当前设计器支持 v1–v4，拒绝 v5 等未知版本。

在仓库根目录导出到一个空目录：

```sh
node scripts/export-project.mjs examples/serial-assistant/quickgui.json artifacts/serial-assistant-runtime
```

在导出目录使用标准工具链构建：

```sh
npm ci
node scripts/build-native.mjs --aot
```

独立工程包含对应运行组件、Rust 引擎、原生串口服务和构建入口；无需设计器参与运行。Windows 与 macOS 应分别在对应系统构建，签名、公证和设备驱动另行配置。

## 验证范围

`tests/serial-demo.test.ts` 检查模板一致性、引用、事件数据契约和默认行为；`tests/e2e/serial-assistant.spec.ts` 检查欢迎入口、可视化编辑、版本升级与浏览器能力诊断。原生串口自动化和实际执行结果另见项目验证记录。

这些用例、PTY 或回环通信不能证明任意实体设备、USB 热插拔/拓扑、不同平台驱动和签名发布均已验收。交付时应按目标系统与真实设备分别记录扫描、参数、收发、拔插、重连和过载恢复结果。
